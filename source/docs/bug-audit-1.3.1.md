# Bug audit and repairs in 1.3.1

This is the technical record for the current source. It separates HGSS retail defects, inherited Sacred Gold/Plus defects, development regressions and build-tool findings. The [release overview](../../BUG-FIXES-1.3.1.md), [retail catalogue](known-bugs-hgss.md), [hack investigation](legacy-bugs-1.3.1.md) and [validation record](ui-1.3.1-validation.md) describe their respective evidence. Source signatures, executed ARM components, rendered scenes and raw-save round trips are different levels of proof.

## Current input and battle-loop repairs

The published input-repeat successor is EN `185dc5c53a75652c021ced65157e1c3388cd661ebe90775e5b49314aee753b08` and IT `b68ddd5691538c3895b75f3f20db5a163b2bd8376629f59d2a9d55dc05935bce`. The shared reader confused held, new and repeated key fields. Correcting offsets to `System+0x48` and `System+0x4C` changes ten bytes per language: two LDR immediates and two CRC32 values. Native remapping/timers, saves, portable Box and other resources are unchanged. Source analysis, full comparison and static derivation prove this delta; they are not new gameplay acceptance.

The battle-freeze predecessor was EN `50ba570f97655cecc7b11bed06eb7f683283b191c1c21f02e49ad55f90fc7665` and IT `c63cf9e993cbee9c38949baf9444dda3e365bddb15840aaa08905d9b02afbedb`. Formal builds matched measured trials byte for byte. The fairy_ai BL at `0x022520C6` also occupies `0x022520C8`; loop return `0x02252138` still targeted the latter halfword. Iteration two executed a BL suffix using an unrelated LR, jumped into data at `0x023D7836` and caused ARM9 data abort `0x0223AB22`. One-byte `D1C6→D1C8` returns to `0x022520CC`, reusing the existing `r1=3*r4`. Payload, ABI, type table, ROM geometry and save layout remain stable.

Twenty full-function EN/IT Unicorn cases fail before and pass after, covering resistance, weakness, immunity, neutral, dual type and Fairy, with stack/register checks and one helper call. A branch-restoring mutant fails readback. Interpreter-only melonDS without JIT/cheats independently reproduced the natural battle error from Continue; changing only that byte in the same state restored menu response. This RAM counterfactual proves causality, not formal-build/save acceptance. Seven overlay-10 callers and one post-KO overlay-12 caller share the callee; Fairy Pokémon are unnecessary. Early exits such as Struggle or Ground versus Levitate are separate.

Physical IT `c63cf9e9…afbedb`, with existing JIT/Compute settings, completed SAVE/cold on an isolated raw copy, passed Weavile/Honchkrow, ran one Houndoom turn and reopened moves. This is not the full Elite Four matrix. **The older Latios freeze is not proven fixed**: it predates this hook and its cause remains unisolated. [AI details](ai-scoring-1.3.1.md) retain the common-callee scope.

### Separate unresolved source-authenticity boundary

Pre/post hashes can match while a same-UID writer substitutes a Python/JSON/C/header/assembly input during consumption and restores it. A real Python import demonstrates it; another same-UID process can chmod/write a0700/0400 copy. Cooperative locks, owner-revocable ACL/flags and a third hash are not an authenticity barrier. Status remains `CONFIRMED / REPRODUCED_COMPONENT / ARCHITECTURAL_HARDENING_REQUIRED / UNFIXED`.

A complete solution needs a broker under another UID or administrative authority, descriptor-relative materialization in a kernel read-only filesystem, then a new protected interpreter/toolchain consuming every input there, with output/scratch elsewhere. Concurrent maintainer-UID writes may alter checkout but must not alter consumed bytes; mount writes must fail and artifact identity must bind to its descriptor-derived manifest. The in-process builder lacks this authority. No partial workaround is promoted as closure.
