# Fairy scalar score: native parent, ARM division and inline return

The installed scalar path is reconstructed and executed from exact r4 EN/IT.
Its native parent differs from V4 only at the four-byte Fairy seam. All 324
monotypes are exercised against both native V4 and current r4, followed by25
literal cases and a failing semantic counterexample per language. The division
is actual ARM code reached by Thumb `BLX`; no service or arithmetic is stubbed.

See the [owner](../../features/fairy-ai/README.md), the preceding
[flags/ELF case](fairy-flags-source-rom-1.3.2.md) and the
[source-to-ROM method](../test-bench.md#linking-source-to-an-exact-rom).
This work adds a reader and tests. It changes no game assembly, type policy,
ROM, save layout or settings.

## Cosa farebbe un professionista di alto livello che non sto chiedendo

Follow the compiled helper backwards to its source/ELF and forwards from the
actual native seam through its stack ABI, decoder and caller return. Distinguish
an inline tail which pops the parent's saved registers from an ordinary leaf
function. Read both `BLX` instructions, their ARM target and both Thumb return
sites, rather than substituting host division.

Use an independent representation of the battle-engine chart for Fairy cases,
but compare ordinary types with the actual inherited scalar function. These are
different oracles: preserving native behavior does not establish agreement with
modern battle policy. Seek duplicate-defender, immunity, order and ABI
counterexamples. Independent Sol6.1 review re-read the regional raw windows,
BLX targets, dense/sparse tables and selected executions without relying on the
integrator's reported conclusions.

IT image retains an `IPKE` header; a header code alone does not prove language.
No save, BIOS, extracted retail data or private capture is distributed or
needed by this case.

Reuse the own-project artifacts generated by the flags tool:

## I metodi e gli strumenti da usare

Dependencies match the flags reader: Python, ndspy, Capstone and Unicorn
(recorded versions3.14.7/4.2.0/5.0.9/2.1.4). The retained build used protected

`--readback-only` for byte/execution checks without a reused-build provenance
claim. Both modes report `local_compilation_performed=false`; only the first
reports `reused_build_verified=true`. Readback-only is exercised separately.
`--json` must name a report distinct from inputs and canonical build artifacts.

### Callers, ABI and execution contract

Three actual overlay12 BLs reach the current parent: `02244726`, `02258920`,
`02258930`. The first belongs to a battle command/hazard path, the latter two to
the post-KO AI selector. These static caller links are bounded to the examined
native consumers; they are not natural gameplay observations or a global proof
that no indirect caller exists.

Entry r0/r1/r2 are attack type, first defender type, second defender type in0–17.
The native parent starts with score40, scans the sparse table and folds each
applicable multiplier by integer division by10. Duplicate defender types count
once. It saves `{r3-r7,lr}` in24 bytes and stores attack type into its r3 home
word. Caller-saved r3 therefore returns as attack type, not its initial cookie.
The tail sees SP=parent−24, attack at`[sp]`, r5/r6 defender types and native score
in r1. It applies the missing Fairy interaction and pops the parent's frame,
returning directly to its caller. It must never execute `02252692` after the
replacement BL. Full return requires original SP, Thumb state and r4–r11.

Both division paths execute ARM instructions, return to Thumb`02252670` or
`02252684`, and preserve their live callee registers. Observed numerators are
bounded0–1600, divisor10, with quotient and remainder checked. This validates
the scalar domain, not a general signed-division implementation. Only declared
Thumb parent/helper and ARM math regions execute; packed data is excluded.
Guest writes stay in the bounded synthetic stack. Stack canaries, resident,
parent, math and sparse-table bytes remain unchanged. Maximum stack depth is24 B
in this domain. Results include executed/read ranges and hashes, instruction
counts, math operands/returns and write bounds.

### Results, counterproof and limits

Each language executes648 monotype parent calls (V4 and r4),25 current literal
cases and one counterexample:674 invocations. Ordinary289 monotypes exactly
preserve inherited scalar results. The35 involving type9 agree with the
independently read current dense engine chart. Literal cases cover scores0,
10,20,40,80,160; duplicate types, dual order, immunity, native double division,
quarter damage and fourfold damage. All5832 type triples are not exercised.

The BEQ which skips a duplicate second defender at owner+76 is replaced with a
NOP only in an explicitly labelled private CPU image. Fairy→Dragon monotype
changes80→160 with two decoder entries while still returning with correct
SP/registers. The literal oracle rejects it. Input ROMs and canonical objects
remain untouched. Nine additional negative checks reject a wrong literal load,
pointer, either BLX, division code, parent seam and forged reused receipt fields.
The two current-image unittest methods pass in both languages with no skips.

Two ordinary differences between native sparse and current dense policy are
confirmed independently: Ghost7→Steel8 and Dark17→Steel8 score20 natively but40
in the dense engine chart. This case proves native equivalence for them, not
policy agreement. A possible correction needs a maintainer decision: changing
the small sparse table/helper would affect the static consumers, require flags
and scalar order/immunity tests, source replay and natural AI/hazard validation.
Implementation cost is small; behavioral scope and validation cost are larger.
No policy change or measured game-performance improvement is delivered here.

Final source/readback runs exited0 in2.073s EN /3.025s IT with OS peak RSS
199,835,648 /206,012,416 bytes, below1GiB. These are host verification costs,
not game timings. Reports and logs are bounded; no new ROM build or capture.

- **Documented provenance:** native reference, exact inputs, own assembly/ELF,
  reused compiler receipt, slot and seam recipes.
- **Reconstructed binary correspondence:**148-byte owner, entire76-byte parent,
 524-byte ARM dependency, verified regional references and dense chart replay.
- **Demonstrated semantics:** exhaustive monotypes plus declared literals,
  real mixed-ISA arithmetic, inline ABI and semantic counterexample.
- **Observed activation:** isolated exact native entry only.
- **Unattributed or untested links:** original native compiler, natural caller
  state, full post-KO score aggregation/AI choice, hazard gameplay, RNG, frame
  timing, SAVE/cold restart and absent hardware remain outside this case.

The reusable extension is a full native-entry runner with actual mixed-ISA
arithmetic and a verified reused build, keeping policy oracles explicit.
Post-KO aggregation is the next linked question; scalar correctness alone does
not establish how its callers combine or use the result.
