# Guarded trainer move strategy

[teams.py](../../sgp13/teams.py) compiles the native hook/core and materializes
[seven trainer configurations](../../sgp13/data/strategic-teams.json). The installer
chains the four native trainer-level sites through this owner and then through
the inherited Plus level hook. The core edits only a matching transient party;
it adds no save field and advances no RNG.

The [rematch native-consumer case](../../docs/validation/rematch-consumer-source-rom-1.3.2.md)
reconstructs the580B code and192B configuration/full512B config allocation, then
executes the actual712/713 exclusion path with all seven ID reads and no buffer
write. It provides exact inputs, toolchain, ELF/readback, caller ABI and portable
verification commands. The seven positive strategy modifications are a distinct
execution coverage question; the rematch exclusion does not qualify them.

The [current positive type3 hook case](../../docs/validation/trainer-strategy-source-rom-1.3.2.md)
now checks the seven configurations on exact r4 inputs: nine substitutions,
once-only108-byte output, Normal fallback, atomic rejection of a late invalid
delta and unchanged inherited level/caller ABI. Six invocations share one
persistent buffer. This stops before CreateMon and does not establish a full
constructor or natural encounter. The [verifier](tools/attribuisci.py) also offers
CPU-free raw/ELF readback; [tests](test/test_attribution.py) check false receipts,
code/config/padding drift, memory bounds and output protection.

The [native move/PP consumer](../../docs/validation/strategy-move-consumer-source-rom-1.3.2.md)
continues the trainer21 edited buffer through four native loads/setters and raw

boundary. It checks PP-Up preservation, all other decrypted bytes and an identical

or trainer construction. [Tool](tools/attribuisci_mosse.py) and
[tests](test/test_move_attribution.py) retain that boundary and fixture provenance.
